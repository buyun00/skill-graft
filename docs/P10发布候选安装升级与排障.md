# P10 范围受限发布候选：安装、升级、卸载与排障

本文适用于 Skill Graft `0.1.1-rc.1` 的两个独立发布包。它是 P10 的**范围受限发布候选**，不是 GA。Local 与 DSH 两轨代码已经合流；本轮验收范围仅覆盖各宿主在各自拥有的工作树上的最小真实路径。两包共同装配冻结的 state、snapshot、pin、request ledger、schema、lock 和 SessionRunner 公共合同，但这不证明同一 probe 的跨宿主物化一致或完整双宿主安全共存。

本文说明预期的发布操作，不代表这些命令已在 P10 全部通过。P10 新真实证据只到四包 pack 与 Local A/B 源码树外 npm install；installed Local/DSH public happy path、真实升级/降级、uninstall/purge 均未验证，准确结果见 [P10 验证记录](../artifacts/verification/P10/README.md)。

## 版本与数据真相

| 维度 | P10 RC | 说明 |
|---|---:|---|
| Application contract | `1` | CLI、HTTP、DSH 都消费同一带版本命令合同 |
| Hub state schema | `2` | 高于当前 schema 的状态只读识别、写入拒绝 |
| Local runtime | `0.1.1-rc.1` | 来自 Local tarball 的 `package.json` |
| DSH runtime | `0.1.1-rc.1` | 来自 DSH tgz 的 `package.json` 与 `build-manifest.json` |
| Library snapshot | `sha256:<64 hex>` | 内容寻址，独立于 runtime 版本；升级 runtime 不自动改变工作树 pin |

Local tarball 与 DSH tgz 必须分别记录代码 SHA、文件清单、字节数和 SHA-256。不要用默认分支名代替已验证代码 SHA，也不要从源码树或 monorepo hoist 运行发布验收。

## Local 发行

### 从 tarball 安装

在新的应用目录和新的 HOME 中安装，`SKILL_GRAFT_HOME` 必须指向明确的数据根：

```powershell
$env:HOME = '<run-root>\local-home'
$env:USERPROFILE = $env:HOME
$env:APPDATA = "$env:HOME\AppData\Roaming"
$env:LOCALAPPDATA = "$env:HOME\AppData\Local"
$env:SKILL_GRAFT_HOME = '<run-root>\local-hub'
npm install --prefix '<run-root>\local-app' '<packages>\ozdqp-skill-hub-0.1.1-rc.1.tgz'
& '<run-root>\local-app\node_modules\.bin\sg.cmd' setup --no-path --no-task --json
& '<run-root>\local-app\node_modules\.bin\sg.cmd' doctor --json
& '<run-root>\local-app\node_modules\.bin\sg.cmd' status --contract-v1 --request-id '<unique-id>'
```

发布验收应确认实际执行的是源码树外绝对 shim；PATH 中不能借用开发树的 `sg`，也不能把 DSH 或 18765 当作 Local 的安装前提。

### 升级与降级保护

升级命令必须从**候选新包**的绝对 `sg` 入口执行。先预览，再提交：

```powershell
& '<new-app>\node_modules\.bin\sg.cmd' upgrade --dry-run --json
& '<new-app>\node_modules\.bin\sg.cmd' upgrade --json
```

升级会复用原安装的 data root、install ID 和 data-root ID，并在生命周期锁/WAL 下切换 runtime、manifest、marker 和命令入口。候选版本必须是严格 SemVer：

- 低于已安装版本的候选在任何生命周期写入、锁或 WAL 之前拒绝；
- 相同版本但不同发布字节拒绝；
- SemVer precedence 相同但仅 build metadata 不同、且发布字节不同，同样拒绝；
- 拒绝后安装 manifest、data marker、root receipt、公开 runtime 和 Hub 数据必须逐字节保持不变。

### 卸载与 purge

```powershell
& '<candidate-app>\node_modules\.bin\sg.cmd' uninstall --json
```

默认卸载只移除 lifecycle installDir 中的命令入口、PATH/用户环境、登录任务和自有 daemon。Hub 数据、snapshot、pin、历史和工作树物化副本保留。用于执行命令的 npm 候选包位于 lifecycle installDir 之外时也会保留；如需移除该包，再对明确的外部 app root 执行 `npm uninstall --prefix <app-root> ozdqp-skill-hub`。

purge 是独立的破坏性动作，只能在确认已卸载后执行，并必须先预览：

```powershell
& '<candidate-app>\node_modules\.bin\sg.cmd' purge --data-root '<run-owned-hub>' --dry-run
& '<candidate-app>\node_modules\.bin\sg.cmd' purge --data-root '<run-owned-hub>' --commit --data-root-id '<uuid>' --plan-hash '<sha256:id>'
```

只对当前明确 run-id 根执行 purge。不得把 OZDQP 活工作树、Skill Graft 中心树、aa1d 交接树或任一阶段工作树作为 data root、install root、package root或递归清理目标。

## DSH 发行

DSH 必须使用独立 `DSH_HOME`，并从 tgz 安装 `dsh.bundle`：

```powershell
$env:DSH_HOME = '<run-root>\dsh-home'
$env:SKILL_GRAFT_HOME = '<run-root>\dsh-hub'
Set-Location '<DeepSeek-Harness-source>'
pnpm run dsh plugin --profile web add '<packages>\ozdqp-skill-graft-dsh-0.1.1-rc.1.tgz'
pnpm run dsh --profile web --dump-config
pnpm run dsh --profile web --host 127.0.0.1 --port <isolated-port>
```

配置必须出现 `@ozdqp/skill-graft-dsh`、Host patch 与 Web Client 声明。DSH 基本能力不得调用外置 `sg`、Local daemon、Codex 或 `127.0.0.1:18765`。

升级用同一隔离 profile 对新 tgz 再执行一次 `plugin add`，随后重新 dump config 并启动。卸载前先停止 profile，再执行：

```powershell
pnpm run dsh plugin --profile web remove '@ozdqp/skill-graft-dsh'
```

remove 后 package link、bundle 配置、页面资源、后台进程和监听应消失；Hub 数据按合同保留。DSH 发行没有单独的 Hub purge 接口，P10 只从 Local run-id 根验证一次 purge。

## 常见排障

| 现象 | 处理 |
|---|---|
| `sg` 指向源码树或旧安装 | 使用 tarball 外装目录下的绝对 shim；检查 `where.exe sg`，不要借用开发 PATH |
| `doctor` 报 package/version mismatch | 不要手改已安装包；从目标候选包执行 `upgrade --dry-run --json` |
| downgrade 被拒绝 | 这是预期保护；保留当前权威，选择版本更高且字节唯一的候选 |
| DSH Web 已 ready，但业务 RPC 空响应 | P10 只允许一次最小重试；仍失败就停止 profile，并记录 transport 限制，不写产品补丁追绿 |
| `LOCK_BUSY` | 当前所有写先取得 `hub-global`；等待 owner 释放后由操作者重试。现有 UI 不展示跨宿主 owner |
| purge 被拒绝 | 核对 data root 已卸载、marker ID 与最新 dry-run planHash；不得绕过保护根或新鲜计划检查 |

## RC 已知限制与 GA 阻断

- **#3 GA 阻断：** 同一 probe 的跨宿主物化尚不宿主中立。Local/DSH runtime asset closure 不同，不能声称 planHash、bytes、marker 或 materialization 一致。正确修复需要版本化 Contracts/Core/marker 迁移，本 P10 不展开。
- **#1 RC 已知限制：** 所有写仍先取得 `hub-global`，不同 probe 也会安全串行，未验证真并行。
- **#2 RC 已知限制：** Local/DSH UI 尚无跨宿主 lock owner 的安全只读投影。
- **#4 RC 已知限制：** DSH Web readiness 后业务 RPC 存在既有空响应时序边界。P10 只允许一次最小重试；仍失败时 installed DSH RPC happy path 标为未验证，composition fallback 不得冒充 DSH bundle RPC。
- **#5 RC 已知限制：** P9 busy 证据是 operator-observed `LOCK_BUSY` 加 exit-0 suffix 副作用证明，不是绿色整链；P10 不重跑该旧阶段 safety，也不升级其证据口径。
- **范围外未验证：** 真实联网 provider、浏览器逐项点击、崩溃/故障注入、性能、长期运行和排列组合矩阵。本 RC 不声明 GA ready 或“两发行安全共存已完整验证”。

P10 主开发任务只封口并推送 `codex/skill-graft-p10-release-candidate`。受限 RC（含 P4–P9 祖先）已获用户授权，在候选分支封口后由**独立干净交付任务**执行 no-ff master 合入并推送 `origin/master`。该操作只是 Git 交付，不等于 GA，不修改远端 default-branch 设置，也不以 `master` 分支名代替候选代码 SHA 或包摘要。
