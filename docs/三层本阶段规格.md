```text

        ▼
```

| 算本阶段 | 不算本阶段 |

## 1. 适配层

**职责：** 把操作系统和外部进程的差异收成端口。核心只看见对象，不看见 `junction` / `stat.ino` / `git -C`。

本阶段适配层是**只读**的。可以判断“这两条路径是不是同一份文件”，不能创建、删除、改 git config。

### 1.1 本阶段应具备

| 能力 | 行为 |
|---|---|
| 路径拼装 | `join` / `resolve` / `dirname` / `basename`，跟本机 Node `path` 一致 |
| 磁盘只读 | 存在性、是否目录/文件、列目录、读文本、mtime、inode+dev、`realpath`；缺文件返回空/false/null，不抛给核心当业务错误 |
| 路径相等 | Win、Darwin：解析后大小写不敏感。Linux：大小写敏感 |
| 链接识别 | 先 `realpath`，再比 inode+dev。Junction、symlink、HardLink 任一接通都算 `isLinked === true`。不能只靠 `realpath`（HardLink 往往解不回“另一个名字”） |
| Git 只读 | `config --get`、任意 `git -C <cwd> …` 的 stdout。失败返回 `null` / `''`，不把 git 非零当异常抛穿 |
| 名单与 JSON | 读 `state.json`、任意 JSON、`#` 注释名单 txt（`attached-worktrees.txt`、`do-not-auto-attach.txt`、`scan-roots.txt`） |
| 装配 | `createHub(hubRoot, overrides?)` 选出本机实现；测试可替换任意端口 |

**本阶段不具备：** `New-HubDirectoryLink` / `New-HubFileLink`、写 JSON、写名单、`skip-worktree`、定位/拉起 Codex、WMI 脱离 Job。这些等写盘阶段再开端口。

### 1.2 应暴露的接口

实现放在 `src/adapters/`，**类型合同**在 `src/core/ports.ts`。新增平台实现必须满足这些方法，不能让核心去 `if (process.platform)`。

```ts
createHub(hubRoot: string, overrides?: Partial<Pick<HubContext, 'fs' | 'git' | 'link' | 'persist' | 'path'>>): HubContext
```

`HubContext`：

| 字段 | 端口 | 本阶段方法 |
|---|---|---|
| `hubRoot` | — | 解析后的绝对路径 |
| `path` | `PathPort` | `join` `resolve` `dirname` `basename` |
| `fs` | `FsPort` | `exists` `isDirectory` `isFile` `readDir` `readText` `statMtimeMs` `statId` `realpath` |
| `link` | `LinkPort` | `samePath(left, right)` `isLinked(linkPath, expected)` |
| `git` | `GitPort` | `configGet(cwd, key)` `output(cwd, args)` |
| `persist` | `PersistPort` | `readJson(file, fallback)` `readList(file)` `readState(file)` |

约定：

- `readList`：去空白行，忽略 `#` 开头。
- `readState`：文件不存在时返回 `{ version: 1, items: [], lastIngest: null }`，不要 `throw`。
- `readDir` 遇到无权限：抛给调用方；核心在扫盘根上自己 `try/catch` 后跳过。
- `createLinkPort(fs, path, platform?)`：`win32` 走 Win；`darwin` 折叠大小写；其它 POSIX 不折叠。

工厂（测试可单测，生产只经 `createHub`）：

| 符号 | 文件 |
|---|---|
| `createHub` | `src/adapters/create-hub.ts` |
| `createLinkPort` / `createWinLinkPort` / `createPosixLinkPort` | `src/adapters/link/` |
| `createNodeFs` `createNodeGit` `createNodePath` `createNodePersist` | `src/adapters/node-*.ts` |

### 1.3 怎么测

适配层测**平台语义**，不测“什么叫客户端仓”。

| 编号 | 断言 | 做法 |
|---|---|---|
| A1 | Win `samePath('E:\\foo', 'e:\\FOO') === true` | `createLinkPort(..., 'win32')`，不依赖本机真是 Windows |
| A2 | Linux `samePath('/tmp/A', '/tmp/a') === false` | `createLinkPort(..., 'linux')` |
| A3 | Darwin 折叠大小写 | `createLinkPort(..., 'darwin')` |
| A4 | HardLink：`isLinked(hard, source) === true` | 临时目录 `fs.linkSync`，走真实 `createHub` |
| A5 | Junction / symlink：`realpath` 对上则 `isLinked` | 本机允许时建链接；无权限则 skip，不能当失败 |
| A6 | 缺文件：`exists` false，`readText` null，`statId` null，`isLinked` false | 假 fs 或临时空路径 |
| A7 | `readList` 丢掉空行和 `#` 注释 | 假 `readText` 或临时 txt |
| A8 | `readState` 缺文件给空状态，坏 JSON 才允许抛 | 缺文件 / 写非法 JSON |
| A9 | `git.configGet` 失败 → `null`；`output` 失败 → `''` | 对非仓库目录调用 |

已有：`test/core-queries.test.mjs` 覆盖 A1、A2、A4。A3、A5–A9 本阶段补测，不阻塞查询命令合入。

## 2. 核心层

**职责：** 领域规则和查询命令。只依赖 `HubContext`，不碰 HTTP、Vue、argv、PowerShell。

### 2.1 本阶段应具备

**规则（写死在核心，不进适配、不进 Vue）：**

| 规则 | 值 |
|---|---|
| 常驻 3 Skill | `ozdqp-development`、`ozdqp-ui-development`、`ozdqp-git-workflow` |
| 挂接后仍保留 | 上列三者 + `unity-skills` + `skills/adopted/*`（本阶段只用来读库存；剥官方树是下一阶段） |
| 客户端仓 | 根上同时有 `AGENTS.md` 和 `baloot_client` |
| 排除目录名 | `ozdqp-skill-hub`、`ozdqp-skill-overlay-kit`、名字含 `.partial-` |
| 排除自身 | 路径等于 `hubRoot` 的不是游戏树 |
| 临时树 | 路径（统一 `/` 并小写）含 `/temp/`、`/appdata/local/temp/`、`/.codex/worktrees/`、`/.config/cursor/worktrees/` |
| 官方仍在盘上 | 树内存在 `.claude/skills` 或 `.codex/skills` |
| override 接通 | `AGENTS.override.md` `isLinked` 到 hub 根上那一份 |
| 已挂接 | 路径出现在 `overlay/attached-worktrees.txt` |
| 禁止自动挂 | 路径出现在 `overlay/do-not-auto-attach.txt` |
| 关联游戏树 | `git config --get ozdqp.gameRepo`（在 **hub** 仓上读） |
| 扫盘根 | `overlay/scan-roots.txt` 下一层目录，再对每个 clone 跑 `git worktree list` |
| 排序 | `changedAtMs` 降序（目录、`.git`、`AGENTS.override.md`、git HEAD/index 的最新 mtime） |

**命令：**

| 命令 | 函数 | 含义 |
|---|---|---|
| `status` | `getStatus(ctx)` | 库存 + inbox 条目 + 计数 + `gameRepo` + `lastIngest` |
| `list-skills` | `listSkills(ctx, gameRepo)` | `resident` / `adopted` / `inbox` 节点；常驻/已采用的 `attached` 相对 `gameRepo` |
| `list-worktrees` | `listWorktrees(ctx)` | 扫盘 + porcelain 解析 + 挂接/链接/官方/临时标记 |

辅助（可单测，不单独作为 CLI 动词）：`isClientCheckout`、`isEphemeralPath`、`parseWorktreePorcelain`、`cloneRootFromCommonDir`、`gameRepoOf`、`listSkillGroup`。

**本阶段不具备：** 改链接、改可见性、搬 inbox、写 state、入队 Codex。核心里若出现这些，就是超范围。

### 2.2 应暴露的接口

对外从 `src/core/index.ts` / `src/index.ts` 导出。控制层只应调用命令函数，不要去 `readDir('skills/inbox')`。

```ts
getStatus(ctx: HubContext): HubState
listSkills(ctx: HubContext, gameRepo: string | null): {
  resident: SkillNode[]
  adopted: SkillNode[]
  inbox: SkillNode[]
}
listWorktrees(ctx: HubContext): WorktreeList
```

`HubState`（`/api/state` 与 `hub status` 同一形状）：

```ts
{
  hubRoot: string
  gameRepo: string | null
  lastIngest: Record<string, string> | null
  resident: SkillNode[]
  adopted: SkillNode[]
  inbox: SkillNode[]
  items: InboxItem[]
  counts: { resident: number; adopted: number; queued: number; proposed: number }
}
```

`SkillNode`：

```ts
{ name: string; kind: 'resident' | 'adopted' | 'inbox'; path: string; hasSkillMd: boolean; attached: boolean }
```

- `path` 相对 hub，正斜杠，例如 `skills/ozdqp-development`、`skills/inbox/project-status`。
- `resident[].attached`：`gameRepo/.agents/skills/<name>` 是否链到 hub 对应目录。
- `adopted[].attached`：同上，目标为 `skills/adopted/<name>`。
- `inbox[].attached` 恒为 `false`（未采用，不往游戏树挂）。
- `counts.queued` / `counts.proposed` 只统计 `items[].status`，不要去数目录。

`WorktreeList`（`/api/worktrees` 与 `hub list-worktrees` 同一形状）：

```ts
{
  scanRoots: string[]
  worktrees: Array<{
    name: string
    path: string
    branch: string
    head: string
    cloneRoot: string
    changedAt: string        // ISO，无 mtime 则为 ''
    changedAtMs: number
    attached: boolean
    doNotAuto: boolean
    officialPresent: boolean
    overrideLinked: boolean
    ephemeral: boolean
    locked: boolean
    prunable: boolean
  }>
}
```

`parseWorktreePorcelain` 输入输出：

- 输入：`git worktree list --porcelain` 文本。
- 输出：`{ path, branch, head, locked, prunable }[]`。
- `branch refs/heads/foo` → `foo`；`detached` → `branch === '(detached)'`。

`InboxItem` 字段与 `skill-review/state.json` 对齐：`id` `name` `unit` `status`，以及可选的 `sourceRef` `oldCommit` `newCommit` `inboxPath` `adoptedPath` `mergeTarget` `note` `createdAt` `updatedAt` `suggestion`。本阶段只读，不改 `status`。

### 2.3 怎么测

核心测**规则**。扫盘、git、真实盘用假端口；本仓只做只读冒烟。

| 编号 | 断言 | 做法 |
|---|---|---|
| C1 | porcelain：普通分支 + detached/locked/prunable | 固定字符串，不调 git |
| C2 | `isEphemeralPath` 命中四类临时路径，普通盘符不命中 | 纯函数 |
| C3 | `isClientCheckout`：缺 `AGENTS.md` 或 `baloot_client` 为假；hub 自身为假；排除名 / `.partial-` 为假 | 假 fs |
| C4 | `getStatus`：本仓 3 条 resident 且都有 `SKILL.md`；inbox 含已入队名；`counts.queued` 与 `items` 一致 | `createHub(真实 hubRoot)` 只读 |
| C5 | `listWorktrees`：名单里的树 `attached === true`；inode/realpath 对上则 `overrideLinked === true` | 假 fs + 假 git |
| C6 | `listWorktrees` 按 `changedAtMs` 降序 | 假 mtime |
| C7 | 扫盘根不可读时跳过，不把整个命令打挂 | 假 `readDir` throw |
| C8 | `gameRepo` 为空时 resident/adopted 的 `attached` 全为 false | 假 `configGet → null` |
| C9 | inbox 节点 `kind === 'inbox'` 且 `attached === false` | 假目录或本仓 |

已有：C1、C2、C3、C4、C5，以及 CLI 冒烟。C6–C9 补测即可。

**禁止**用核心单测去 `attach-library.ps1` 或改已挂的 `ozdqp-main-fix`。

## 3. 控制层

**职责：** 把人的动作变成核心命令。本阶段控制层是**只读门面**：CLI 打字、HTTP 转发、Vue 展示。策略已经算完了，控制层不得重算。

### 3.1 本阶段应具备

| 入口 | 应做 | 不应做 |
|---|---|---|
| CLI `ozdqp-hub` | `status` / `list-worktrees` / `list-skills` / `-h`；JSON 打到 stdout | 写盘、起 Codex、静默 attach |
| HTTP | `GET /api/state` → `getStatus`；`GET /api/worktrees` → `listWorktrees`（可 30s 缓存） | 自己 `readdir`、自己比 inode、自己拼 worktree porcelain |
| Vue | 工作区 / Skills / 待审只消费上述 JSON | 再实现一套“算不算挂上” |
| 启动 | `start-panel.ps1` 在拉起 Node 前 `npm run build`（`dist/` 过期则重编） | 编译失败仍起旧逻辑 |
| Hook | **维持现状**（仍调 `.ps1`） | 本阶段不改 hook |

HTTP 里尚未迁走、本阶段允许继续留在 `panel/server/index.mjs` 的：`/api/skill`、`/api/history`、`/api/decide`、`/api/analyze`、`/api/codex/*`、`/api/worktree/attach|detach`。它们不是本阶段控制层的“应具备”，是过渡。新查询不要再往这个文件里堆逻辑。

### 3.2 应暴露的接口

**CLI**

```text
npm run hub -- status
npm run hub -- list-worktrees
npm run hub -- list-skills
npm run hub -- --help
```

| 项 | 约定 |
|---|---|
| 成功 | 退出码 0；stdout 是格式化 JSON，形状等于核心返回值 |
| 未知命令 / 缺命令 | 退出码 1；用法走 stderr 或 stdout（`--help` 为 0） |
| hub 根 | `HUB_ROOT`，否则为仓库根（`dist/control/cli.js` 上两级） |
| 编码 | UTF-8，无 BOM |

**HTTP（本阶段冻结的查询面）**

| 方法 | 路径 | 体 | 200 体 |
|---|---|---|---|
| GET | `/api/state` | 无 | `HubState` |
| GET | `/api/worktrees` | 无 | `WorktreeList` |
| GET | `/api/health` | 无 | `{ ok: true }` |

同一进程里，`GET /api/state` 与 `hub status` 字段一致（`worktrees` 缓存最多差 30s，测一致性时先打 CLI 或清缓存）。

**Vue**（`panel/src/api.ts`）只允许：

```ts
api.state(): Promise<HubState>
api.worktrees(): Promise<WorktreeList>
```

禁止在 `.vue` 里读 `attached-worktrees.txt` 或 `fs.stat`。

### 3.3 怎么测

控制层测**转发与形状**，不测“什么叫客户端仓”（那是 C3）。

| 编号 | 断言 | 做法 |
|---|---|---|
| U1 | `hub status` 退出 0，`JSON.parse` 后有 `hubRoot`、3 条 resident | `spawn` `dist/control/cli.js` |
| U2 | `hub list-worktrees` 含 `scanRoots` 与 `worktrees` 数组 | 同上 |
| U3 | `hub list-skills` 有三类数组 | 同上 |
| U4 | 未知命令退出非 0 | `hub nope` |
| U5 | 面板起来后 `GET /api/state` 与 `hub status` 的 `resident`、`counts.queued` 一致 | 活面板或测试服 |
| U6 | `GET /api/worktrees` 对 `E:\ozdqp-main-fix`：`attached === true` 且 `overrideLinked === true` 且 `officialPresent === false` | 活面板；与现网挂接约定绑定 |
| U7 | HTTP 查询 handler 源码不再出现 `readdir` / `statSync` / `ino`（会话/静态文件除外） | 审 `handleApi` 的 state/worktrees 分支，或 grep |
| U8 | 回归：`npm run test:attach` | 面板须在 `127.0.0.1:18765` 监听 |

已有：U1（部分）、U6、U8。U2–U5、U7 作本阶段收尾检查。
