# 中心库版本、融合、替换与回滚语义

本文定义 Skill Graft 在中心库、工作区和已连接关系之间的严格操作语义。当前网页成品由 `panel` 的 `ProductApp` 提供界面，`server/product-service.mjs` 提供产品 API；fixture 只用于隔离验收，不改变这些语义，也不能替代尚未完成的真实路径证据。

## 1. 不可变版本模型

### 1.1 版本是完整状态

中心库版本不是一组零散文件的临时复制，而是某个时刻中心库的完整逻辑状态，至少包含：

- 体系、Skill 和 Agent 规则内容。
- 每项内容的来源路径、宿主投影和归并依据。
- 父版本（首次版本没有父版本）。
- 用户选择、变更摘要和生成时间。
- 被排除、保留或标记为私有的发现说明。

### 1.2 版本不可变

版本一旦保存：

- 不允许原地修改、覆盖或删除。
- 任何用户编辑、AI 修改、融合或恢复都必须生成新版本。
- 历史比较以版本内容为准，不依赖当前工作区是否仍存在。
- “恢复旧版本”不是把历史抹掉，而是以旧版本内容创建新的恢复版本，并保留恢复来源。

### 1.3 草稿、预览和保存

一次变更依次经过以下状态：

1. **草稿**：用户编辑或 AI 建议形成的未保存内容；不改变当前版本。
2. **变更预览**：系统计算出文件、体系和保全范围的具体差异；仍不写入目标。
3. **确认**：用户确认变更范围、冲突处理、私有边界和保护点。
4. **保存为新版本**：原子地产生新的中心库版本，并记录父版本及变更摘要。
5. **完成或恢复**：完成后显示新版本；写入失败则按失败语义恢复，不产生伪成功版本。

关闭页面、取消或返回不会把草稿误当成中心库版本。若产品保留草稿，必须明确标注“未保存的变更”。

## 2. 写入边界与安全不变量

### 2.1 中心库写入

中心库只在用户确认“创建中心库 v1”“生成中心库新版本”或“保存为新版本”后写入。分析、比较、查看来源和聊天本身不改变中心库。

### 2.2 工作区写入

工作区只在用户明确选择“使用中心库接管此工作区”、查看变更预览并确认后写入。融合进中心库不会反向修改来源工作区。

### 2.3 私有和未知范围

以下范围默认受保护：

- 被识别为可能项目私有的 Skill 或规则。
- 无法确认归属的目录和文件。
- 用户脏改、未知文件及未纳入中心库的体系。
- 缓存、PackageCache、备份目录和链接目标之外的内容。

系统不得仅凭“发现了”“同名”或“看起来重复”删除、覆盖、上传或替换上述内容。若用户明确选择处理，预览必须逐项列出范围和后果。

### 2.4 失败安全

任何写入流程都必须满足：

- 写入前可看到目标、路径、动作和保全范围。
- 能区分已完成、未开始、部分完成和已恢复。
- 出错时不能把部分结果标记为完整成功。
- 中心库版本保存和工作区接管不能依赖静默清理或重置用户文件。

## 3. 首次初始化：创建中心库 v1

1. 用户选择工作区并启动只读分析。
2. 系统识别活跃体系、别名、重复投影、版本差异、缓存、备份、休眠缺失和声明未落盘项。
3. 用户选择要纳入中心库的体系；默认不纳入缓存、备份、缺失和未明确授权的疑似私有体系。
4. 系统展示 v1 预览：纳入内容、来源路径、归并关系、排除项和“原工作区不变”的边界。
5. 用户确认后建立完整中心库 v1。
6. v1 以当前选择为唯一初始基线；未选择项仍保留在分析结果中，但不能隐式进入中心库。

初始化不会接管工作区，也不会因建立中心库而删除、移动、清理或覆盖来源文件。

## 4. 融合进中心库

### 4.1 适用场景

用户希望将另一个工作区中发现的新体系、更新或差异纳入中心库，同时保持来源工作区原状。

### 4.2 操作步骤

1. 选择工作区并进行只读分析。
2. 将分析结果与当前中心库版本比较。
3. 按体系显示新增、更新、相同、冲突、缓存和疑似私有内容。
4. 用户选择要融合的体系；默认不处理未授权私有内容。
5. 对冲突进行选择或手动合并。
6. 生成变更预览，列出中心库将新增、修改、排除和保留的内容。
7. 用户确认后，以当前中心库版本为父版本生成新的中心库版本。
8. 来源工作区保持不变；连接关系记录来源路径和本次接受的版本基线。

### 4.3 融合结果

- “相同”内容不重复生成第二份逻辑来源。
- 完全重复内容保留来源关联，但中心库只保留一个内容实体。
- 同一后端的不同宿主投影可共同归入一个体系，同时保留投影差异。
- 同一体系的不同版本必须明确选择采用哪个版本，或保留为可比较的变体。
- 缓存、备份、休眠缺失和声明未落盘项不会因为比较而自动转为活跃内容。

## 5. 使用中心库接管工作区

### 5.1 适用场景

用户希望让选定工作区使用中心库中的体系，但要求明确知道会改动什么、会保留什么，以及失败后如何恢复。

### 5.2 保护点

接管确认前必须建立保护点，至少说明：

- 保护点对应的工作区路径。
- 被保护的受管理范围及必要的用户边界。
- 生成时间、大小或可识别标记。
- 恢复入口和恢复后再次检查方式。

旧有备份必须保持原样；新的接管保护点不得覆盖旧备份或以含糊名称复用旧备份。

### 5.3 接管预览

预览至少分三类：

1. **将新增或更新**：中心库中有、目标工作区缺少或版本不同的受管理内容。
2. **将保留**：未知范围、可能私有内容、用户脏改及未纳入体系。
3. **不会处理**：缓存、备份、声明缺失项或超出本次选择的范围。

如果某个目标文件同时存在用户修改和中心库更新，必须先显示冲突并要求选择，不能静默覆盖。

### 5.4 接管应用

用户确认后，只写入预览中明确列出的受管理范围。应用结束后重新分析目标工作区并显示：写入成功项、保留项、跳过项和异常项。建立连接关系不等于获得删除、上传或处理私有内容的授权。

## 6. 已连接工作区的上游更新

已连接工作区出现新增或更新时，不建立另一套“同步协议”。统一复用以下流程：

1. 发现变化。
2. 只读分析并以最近接受的中心库版本为参照。
3. 比较新增、更新、相同、冲突和私有边界。
4. 用户选择要融合的体系。
5. 解决冲突并预览。
6. 生成新的中心库版本。
7. 如需写回工作区，再从同一版本进入“使用中心库接管此工作区”的预览和保护流程。

“稍后处理”只暂停本次变化，不丢弃来源信息，也不自动应用变化。

## 7. 冲突语义

冲突是指当前中心库版本与来源工作区或目标工作区对同一逻辑内容存在无法安全自动选择的差异。冲突至少显示：

- 涉及的体系、Skill 或规则文件。
- 中心库版本和工作区来源。
- 两侧的内容变化摘要。
- 是否可能包含用户私有内容。
- 选择后会影响哪些目标。

用户可选择：

- 保留中心库版本。
- 使用工作区版本。
- 手动合并后继续。
- 跳过该体系，稍后处理。

未解决的必需冲突阻止生成新版本或接管应用。跳过的体系不应被标记为已融合或已接管。

## 8. 取消、失败、重试与恢复

### 8.1 取消

- 分析阶段取消：只停止读取，不写中心库或工作区。
- 比较和预览阶段取消：保留或丢弃未保存草稿均需明确提示，不生成版本。
- 融合确认前取消：中心库保持原版本，来源工作区保持原状。
- 接管确认前取消：目标工作区保持原状，不生成保护点以外的写入。

### 8.2 失败

失败页面必须使用用户可行动的表达，例如“无法读取 `path\file.md`，可能被其他程序占用”，并提供重试、跳过或返回预览。不能只显示内部状态名称或空白错误。

中心库保存失败时，原版本仍可用，失败草稿不得冒充新版本。接管失败时，系统应恢复到保护点；如果恢复也失败，必须明确显示已写入范围、未恢复范围和人工恢复入口。

### 8.3 重试和幂等

重试应基于本次分析和预览的明确结果，不重复创建相同版本或重复覆盖用户内容。若来源在等待期间发生变化，应重新分析并提示预览已过期，而不是套用旧预览。

## 9. 回滚语义

### 9.1 中心库回滚

从版本历史选择“恢复为此版本”会：

1. 读取所选旧版本的完整内容。
2. 将其与当前版本比较。
3. 生成恢复变更预览。
4. 用户确认后创建新的中心库版本。
5. 在新版本中记录“恢复自 vX”的来源。

旧版本和中间版本仍可比较，不能通过回滚抹掉历史。

### 9.2 工作区回滚

接管失败或用户明确选择恢复时，使用本次接管生成的保护点恢复目标工作区。恢复范围只能覆盖保护点实际保留的受管理变更；原本未纳入接管的私有、未知和用户脏改不能被保护点恢复动作删除。

恢复完成后必须重新分析工作区，显示恢复成功、保留和异常项。恢复不是新的接管授权，也不会自动把工作区重新融合进中心库。

## 10. 用户可见状态与内部实现隔离

主流程使用“分析结果”“纳入范围”“变更预览”“正在处理”“操作记录”“技术详情”等词。内部的快照、声明、计划同步、Runner、会话视图、账本、锁、命令和事件只能作为高级诊断信息，不能替代对话正文或用户可理解的操作阶段。

## 11. 严格不变量与验收条件

- 分析和比较永远是只读操作。
- 中心库版本永远不可变；任何变更和恢复都追加新版本。
- 融合永远不修改来源工作区。
- 接管永远先有预览和保护点，再有写入。
- 未明确选择的私有或未知内容永远不被删除、覆盖或上传。
- 未解决的必需冲突永远阻止生成新版本或接管。
- 取消操作不留下未声明的半成品写入。
- 失败结果不能标记为完整成功；恢复失败必须显示范围和证据。
- 上游更新必须复用发现、比较、融合、新版本这条路径。
- 版本历史、比较和恢复必须可从中心库页面进入。

## 12. 实现与验证边界

生产 UI 已迁入 `panel`，并通过 `server/product-service.mjs` 对接只读分析、中心库初始化、比较、草稿、版本、接管预览/应用/恢复和 AI 聊天接口。真实浏览器验收固定使用隔离数据根和 `http://127.0.0.1:18865/`；`E:\ozdqp-main-fix` 只允许读取、不得 attach 或写入。

页面可点击不等于每条后端路径已经验收。融合、接管、回滚、失败恢复、真实上游更新和私有 Skill 防护的完成状态，必须以《验证记录》和《真实路径测试文档》中列出的浏览器证据为准。安装态、任务计划、现有端口服务和旧备份不属于本次写入范围。
