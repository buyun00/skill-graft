### 1.1 成品能力与验收边界

当前成品的“选择工作区”由服务端调用 Windows 原生文件夹选择能力；已确认网页可以发起选择器。由于本自动化环境无法枚举或操作由 PowerShell 持有的模态窗口，浏览器验收在选择器未完成时使用网页内的兼容路径输入继续后续真实 API 流程。该兼容输入不是原生选择器的替代实现，最终桌面验收仍需人工在资源管理器中完成一次选择。

当前成品由 `panel` 导出的网页连接 `server/product-service.mjs`；中心库初始化、分析、比较、草稿、版本、接管预览/应用/恢复和聊天均通过产品 API 工作。本次浏览器验收把 `SKILL_GRAFT_HOME` 指向独立临时数据根，真实工作区只读；融合、接管、回滚和上游更新的完成状态仍以本文件末尾的已验证/待验证清单为准。

## 3. 开始前只读基线

在打开浏览器前，只读取并保存摘要，不把正文或私有内容拷贝进证据：

```powershell
$workspace = 'E:\ozdqp-main-fix'
$installRoot = 'C:\Users\win11\AppData\Local\skill-graft'
$dataRoot = 'C:\Users\win11\AppData\Local\skill-graft-data'
$oldBackup = 'C:\Users\win11\AppData\Local\skill-graft-data-backup-20260825-212458'

Get-Item -LiteralPath $workspace,$installRoot,$dataRoot,$oldBackup -Force |
  Select-Object FullName,Attributes,LastWriteTime

git --no-optional-locks -C $workspace status --porcelain=v1 --untracked-files=all
git --no-optional-locks -C $workspace branch --show-current
git --no-optional-locks -C $workspace rev-parse HEAD

Get-FileHash -LiteralPath (Join-Path $workspace '.git\index') -Algorithm SHA256
```

预期只读基线：

- 工作区分支为 `main`，HEAD 为 `c992cc988614aaa5f2811c28aa090496cb936d68`，相对 `origin/main` 为 ahead 0 / behind 92。
- 工作区有 10 个已修改文件、11 个未跟踪文件；这不是测试失败，而是必须保全的用户现场。
- index SHA-256 为 `2a5f2d47184060dbab53778f5ecf37156c4de5b293f2db02bf8efce476538877`。
- 安装根、数据根、旧备份均存在；旧备份不得被当成当前中心库写入目标。

测试结束后重新运行同一组命令。工作区 status、index 哈希和 mtime 必须保持不变；任何变化都应立即停止并记录为越界，不得用 reset/checkout 清理。

## 7. 其他流程的最小检查清单

### 7.1 已连接工作树出现上游新 Skill

使用已连接的 incoming fixture 产生一个受控 Skill 更新，然后从首页进入：`发现变化` → `比较` → `融合` → `中心库新版本`。本次第一步只列出 1 个有内容变化的 Skill 和 1 个文件；第二步显示该文件的 GitHub 风格 `+1/-0` diff 和统一 AI 输入框；真实 AI 处理成功后第三步显示完整可编辑的最终文件，只有第 9 行使用绿色标识本次变更。最后取消，未生成 v3。不新增 snapshot/claim/planSync 等学习门槛。

### 7.2 冲突、取消和失败

- 分析中取消：回到上一页面，零写入。
- 同名不同哈希：进入左右比较，默认不覆盖。
- 用户拒绝某个私有 Skill：继续流程，私有文件保持原样。
- 保存新版本失败：中心库保持旧版本，显示恢复入口；工作树仍不变。
- 接管预览取消：不生成备份、不改工作树、不改 Git index。
- 失败恢复成功后：历史中不产生伪造的“已应用”记录。

### 7.3 正常 AI 聊天

助手页必须显示正常的用户消息和 AI 回答正文。typed command、session event、lock、ledger、runner progress 只能放在可展开的“技术详情”。当前已在隔离服务上实际发送“请用一句话说明中心库的作用，不要修改任何文件。”并看到 AI 正文回答；更新流程中的统一 AI 处理也已在隔离 fixture 上成功。涉及普通聊天直接发起文件变更、任意工具调用和完整会话持久化的路径仍待补证据。
