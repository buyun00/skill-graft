# Skill Graft 页面与交互规格

> 状态：生产 UI 规格（已迁入 `panel`，由导出网页提供入口）
> 范围：首次初始化、中心库、工作区分析、融合、接管、版本化、回滚与 AI 助手。
> 实现：界面由 `panel/src/components/ProductApp.tsx` 与 `panel/src/app/product.css` 提供，服务端产品能力由 `server/product-service.mjs` 提供；隔离验收可使用 fixture，但不得把 fixture 当作真实工作区结果。

## 1. 目标与默认信息架构

### 1.1 设计目标

Skill Graft 的用户是拥有多个 Git 工作树、希望让 AI 工具共享一套可靠 Skill/Agent 规则的开发者。用户需要回答的是“我的规则在哪里、哪些其实是同一套、这次要保留什么、应用后能否恢复”，而不是理解 snapshot、claim、planSync、Runner 或会话协议。

默认原则：

- 先选择工作区，再只读分析，再由用户选择，最后才允许写入。
- 中心库版本不可变；手改、AI 修改、融合、接管都必须先预览并形成可回滚边界。
- 物理路径是证据，不是用户操作门槛。路径可以在详情中查看，但不能取代“选择工作区”按钮。
- 体系是面向用户的管理对象；Skill、Agent 规则、宿主投影和来源路径是体系下的内容与证据。
- 不把项目私有 Skill 当成可上传、覆盖或删除对象；除非用户逐项明确选择，否则保留原位。
- “连接新工作区”和“已连接工作区发现上游变化”复用同一条发现变化 → 比较 → 融合/接管 → 预览 → 应用流程。
- 技术状态、事件、锁、日志和原始 JSON 只在“技术详情”中出现。

### 1.2 默认导航

默认只显示四个主导航：

| 导航 | 用户问题 | 首要动作 |
| --- | --- | --- |
| 首页 | 现在是否需要我处理什么？ | 连接工作区 / 查看待处理变化 |
| 中心库 | 我正在管理哪套 Skill/Agent 规则？ | 查看、手改、让 AI 修改、查看版本 |
| 工作区 | 哪些工作区已接管，谁有变化？ | 选择工作区、重新分析、断开 |
| AI 助手 | 我可以直接用自然语言询问或修改什么？ | 发送消息、查看变更预览 |

以下内容不是默认导航项：

- 首次使用向导：未初始化时的全屏入口。
- 分析与变更：从“连接工作区”或“发现变化”进入的上下文流程页。
- 版本历史：中心库内的 Tab/抽屉，必要时打开全屏比较。
- 设置：头像菜单或页面底部入口。
- 高级诊断：设置内折叠入口，默认不加载到主操作区。
- 更新中心、商店：不再作为独立主流程；变化回到首页和分析流程。

生产 UI 路由（导出网页与服务端入口保持一致）：

```text
/                  首页
/setup             首次使用向导
/library           中心库
/library/history   版本历史（上下文页）
/workspaces        工作区
/changes           分析、比较、融合、接管（上下文页）
/assistant         AI 助手
/settings          设置
/settings/advanced 高级诊断（隐藏）
```

### 1.3 全局状态与状态文案

主界面只使用以下用户可理解的阶段：

| 内部阶段 | 默认 UI 文案 | 用户能知道什么 | 可用动作 |
| --- | --- | --- | --- |
| idle | 等待你的操作 | 没有任务正在执行 | 开始分析 / 连接 |
| reading | 正在只读分析工作区 | 尚未写入任何文件 | 取消 |
| ready | 分析完成 | 可以查看发现结果 | 选择体系 / 查看详情 |
| needs_choice | 有内容需要你决定 | 体系归并或冲突尚未定案 | 选择 / 解决冲突 |
| preview | 预览已准备好 | 写入范围和保全边界已计算 | 查看差异 / 返回修改 |
| applying | 正在应用变更 | 已确认，正在按预览执行 | 查看进度（折叠详情） |
| succeeded | 已完成 | 新版本或连接已产生 | 查看版本 / 查看工作区 |
| cancelled | 已取消，未应用变更 | 预览仍可丢弃或继续 | 重新开始 |
| failed | 未完成，工作区没有被继续修改 | 失败原因与恢复点可见 | 重试 / 保存证据 / 返回 |

状态颜色不能单独承载语义：同时显示文字和图标，并用 `aria-live="polite"` 报告阶段变化。

## 2. 全量屏幕与状态地图

```text
首次进入
  └─ 未初始化 → /setup
       选择工作区 → 只读分析 → 选择体系 → 创建中心库 v1
                                      ├─ 取消/失败：回到上一步，零写入
                                      └─ 完成：/ 首页（中心库 v1）

首页 / 工作区
  └─ 选择另一个工作区 → /changes?stage=analyzing
       只读分析 → 发现体系 → 用户选择
          ├─ 融合进中心库 → 比较 → 解决冲突 → 预览 → 保存中心库新版本
          └─ 使用中心库接管 → 预览工作区写入/保全 → 明确确认 → 接管完成

已连接工作区
  └─ 发现上游变化 → 复用 /changes 同一条流程
       发现变化 → 比较 → 融合或接管 → 新版本/新工作区状态

中心库
  ├─ 查看体系/Skill/Agent 规则/来源
  ├─ 手动修改 → 草稿 → 差异预览 → 保存为新版本
  ├─ AI 修改 → 对话 → 变更卡片 → 差异预览 → 保存为新版本
  └─ 版本历史 → 比较 → 回滚预览 → 生成恢复版本

AI 助手
  └─ 用户消息 ↔ AI 回复
       ├─ 普通回答：继续对话
       ├─ 需要变更：展示变更预览卡片
       └─ 技术详情（折叠）：状态、事件、日志、请求标识
```

所有变更流程均有四条可退出路径：返回选择、取消（不写入）、失败后重试、成功后查看证据。浏览器刷新时，生产 UI 应从服务端持久状态恢复当前流程，而不是从事件日志推断；隔离验收可保留当前 screen/stage fixture 以复现页面。

## 3. 页面规格

### 3.1 首次使用向导 `/setup`

#### 首屏布局

- 顶部：Skill Graft 标识、四步进度条“选择工作区 / 只读分析 / 选择体系 / 创建中心库”。
- 主卡：标题“先选择一个工作区”，说明“Skill Graft 会读取其中的 Skill、Agent 规则和 Git 记录，分析不会修改文件”。
- 路径选择行：按钮“选择工作区”，成功后显示工作区名称和完整路径；不提供以文本框为主的绝对路径输入。
- 安全说明：只读范围、不会上传私有 Skill、不会删除未选择内容。
- 底部按钮：主按钮“开始只读分析”，次按钮“取消”。未选路径时主按钮禁用。

#### 交互与状态

- 初始空态：显示选择按钮和“尚未选择工作区”。
- 选择中：按钮显示“正在打开文件夹选择器…”，不能重复触发。
- 已选：显示“已选择”，允许“更换工作区”；开始分析前再次确认路径。
- 分析中：阶段标题“正在只读分析”，显示已扫描来源类型，不显示 Runner 或事件流。
- 分析失败：显示“未能读取此工作区”，说明权限/不存在/路径不是目录等原因；按钮“重新选择”和“重试分析”。承诺“没有写入工作区”。
- 分析完成：进入体系选择，不自动创建中心库。

#### Windows 原生文件夹选择器产品契约

1. `选择工作区` 必须调用桌面宿主提供的 Windows 原生文件夹选择能力（资源管理器式目录选择）；主流程不得要求用户复制粘贴绝对路径。
2. 宿主返回规范化绝对目录路径、显示名称、可读性、Git 根判断和选择取消结果。路径在 UI 仅作为确认和证据展示。
3. 选择器取消是无错误的 `cancelled`：保留上一步状态，不创建会话、不分析、不写入。
4. 选择结果必须验证：存在、是目录、当前用户可读；Git 工作树不是硬性条件，但非 Git 目录须明确提示分析范围。
5. 不能把 `E:\ozdqp-main-fix` 等示例路径预填为真实目标；fixture 只用于隔离验收演示，真实连接仍须由用户选择路径。
6. 文件夹选择和分析均为只读。连接、融合、接管必须是后续显式动作，不能因选择目录而自动 attach。
7. 生产桌面宿主通过服务端的原生选择器能力返回 Windows 路径；在无法自动操作 PowerShell 模态窗口的浏览器验收环境中，使用页面内兼容路径输入继续验证后续流程，并在证据中明确标注。不得将 `<input type=file>` 的文件列表冒充真实 Windows 目录选择器。

### 3.2 首页 `/`

#### 首屏布局

- 顶部只用一句标题说明用途：“现在要做什么？”；副标题为“先看有没有新修改，也可以直接进入工作树、中心库或 AI 助手”。不显示问候语、项目方案版本、最近活动或原则说明。
- 第一行是唯一的状态栏“新修改”。有变化时显示发生修改的 Skill 数、文件数、来源工作树和“查看修改”；无变化时显示“没有待处理的新修改”和“重新检查”；未连接时引导“连接工作树”。隔离验收 build 可额外保留一个弱化的“演示有新修改”触发按钮，生产默认不把演示入口作为真实来源。
- 第二行是三个快捷入口，不在首页重复各管理页的完整内容：
  1. “工作树”显示已连接数量、一个当前工作树摘要以及“查看工作树”；
  2. “中心库”只突出当前 Skill 总数以及“打开中心库”，不显示版本号；
  3. “AI 助手”提供一个快速输入框和“开始对话”，提交后进入完整 AI 对话页并显示刚才的用户消息与 AI 回答。
- 全局搜索只搜索中心库、工作区和变化，不让搜索结果暴露内部 API 名称。

#### 状态、空态与失败态

- 首次空态：主 CTA“选择第一个工作区”，旁边解释会创建“中心库 v1”。
- 有未处理变化：橙色提示卡，但主按钮使用具体动词“查看变化”，不用“处理更新”。
- 首页快速 AI 输入为空时不创建对话；提交有效内容后创建新对话并跳转 `/assistant`，首页不展开聊天历史。
- 后端不可用：显示“暂时无法读取中心库状态”，保留已知本地数据和“重试”，技术原因置于“技术详情”。
- 断开后：工作区卡片显示“未连接”，中心库不被删除，提供“重新连接”。

### 3.3 中心库 `/library`

#### 首屏布局与组件

- 标题“中心库”，版本徽章“v1”；右上按钮“查看历史”“让 AI 修改”。
- 左侧体系列表：名称、来源数量、Skill/规则数量、状态；支持搜索和按“全部 / 活跃 / 私有 / 有差异”筛选。
- 右侧内容区：体系摘要、Skill 列表、Agent 规则入口、来源路径、最近版本；选中 Skill 后显示文件内容和“手动修改”。
- 每个来源可展开查看原始路径、宿主投影、别名/缓存关系和发现时间。

#### 关键动作

- “手动修改”：打开编辑草稿，顶部显示“当前为草稿，尚未写入中心库”。
- “让 AI 修改”：跳转助手并携带体系上下文；AI 必须返回变更预览卡，而不是直接保存。
- “查看差异”：左右或 unified diff，显示新增/修改/删除文件数和私有文件保全说明。
- “保存为中心库 v2”：只在预览无未解决冲突且用户确认后可用。
- “丢弃草稿”：二次确认，说明不会影响已保存版本。

#### 空态与失败态

- 中心库无版本：引导“从首次分析创建中心库 v1”，不显示 snapshot/claim 表单。
- 没有体系：显示分析可能未发现 Skill/Agent 入口，并提供“重新分析工作区”。
- 文件读取失败：保留体系卡片，内容区显示“此来源暂时不可读”，按钮“重试读取”；不能静默用缓存覆盖当前内容。

### 3.4 工作区 `/workspaces`

#### 首屏布局

- 顶部主按钮“选择并分析工作区”；已连接工作区列表按“需要处理 / 正常 / 未连接”分组。
- 工作区卡片：名称、规范化路径、最近分析时间、发现体系数、中心库版本、状态说明。
- 已连接卡片按钮：“查看变化”“重新分析”“查看接管记录”；未连接卡片按钮“连接”。
- “断开连接”放入更多菜单，明确断开不会删除中心库，也不会清理项目私有 Skill。

#### 状态与空态

- 空态：“还没有连接工作区”，主按钮“选择工作区”。
- 正常：“已连接到中心库 v2”。
- 有变化：“发现了 2 个新 Skill，等待比较”。
- 分析中：“正在只读分析”，提供取消。
- 失败：“上次分析未完成，未修改工作区”，提供重试和查看技术详情。

### 3.5 分析、比较、融合、接管 `/changes`

这是从首页、工作区和上游变化进入的复用流程，不在默认导航中单独暴露协议概念。

#### 阶段 1：发现结果

- 顶部进度：“1 分析 / 2 选择 / 3 比较 / 4 应用”。
- 摘要：“在 `E:\ozdqp-main-fix` 整理出 7 类候选；检测到 21 行 Git 脏状态、571 个 skip-worktree 且物理缺失条目，以及 2 个声明未落盘条目”。候选类别为 Unity MCP CLI、UnitySkills REST、AIGameTesting 私有体系、项目规则入口、Git 休眠体系、声明未落盘、缓存与备份。
- 体系卡片见第 4 节；默认只勾选可确认的活跃体系，缓存、休眠、声明缺失和私有体系不自动导入。
- 主按钮“继续选择”，次按钮“退出分析”。退出不会写入。

#### 阶段 2：双主选择

只给用户两个主要选择：

1. **融合进中心库**：保留中心库和工作区中有价值的内容，比较后生成一个新的中心库版本。
2. **使用中心库接管此工作区**：先预览将替换/创建的托管链接和规则投影，再明确确认。

高级入口“逐体系选择”允许专家改变单组决定，但默认折叠，并说明会增加判断成本。

#### 阶段 3：比较与预览

- 顶部明确两侧：“中心库 v1”与“工作区发现内容”；显示体系、文件和规则数量。
- 过滤器：“全部 / 新增 / 修改 / 冲突 / 保留不动”。
- 差异行显示文件相对路径、来源、变更类型、是否私有、用户决定。
- 底部安全栏显示“将写入”“保全不动”“需要解决”；主按钮“生成应用预览”。
- 预览不是应用；主按钮在此阶段只能是“确认并生成预览”，不能叫“执行 sync”。

#### 阶段 4：应用结果

- 融合成功：“中心库 v2 已创建”；按钮“查看 v2”“返回首页”。
- 接管成功：“工作区已接管中心库 v2”；按钮“查看工作区”“查看接管记录”。
- 失败：“没有完成应用，未继续修改工作区”；显示恢复点和“重试应用 / 返回比较”。
- 取消：“已取消，预览仍未写入”；如果已有备份，明确显示其位置和恢复按钮。

### 3.6 版本历史 `/library/history`

- 时间线按 v1、v2、v3 显示版本名称、创建原因、来源工作区、变更摘要和影响体系。
- 操作：“比较版本”“查看文件”“预览回滚”。
- 回滚语义：回滚是从目标历史版本生成一个新的恢复版本，例如当前 v3 回滚到 v1 后产生 v4（恢复自 v1）；不删除 v2/v3。
- 回滚预览必须显示将改变的体系、文件、工作区投影和保全边界；确认按钮“创建恢复版本”。
- 空态：“还没有版本历史”；初始化完成后至少有中心库 v1。
- 失败态：“无法创建恢复预览，现有版本未改变”，提供重试和证据详情。

### 3.7 AI 助手 `/assistant`

#### 正常对话布局

- 左侧为最近对话标题和时间，不显示 session ID 作为标题。
- 主区使用聊天气泡：用户消息右对齐，AI 回复左对齐；支持 Markdown、代码和文件引用。
- 输入框 placeholder：“告诉助手你想查看、修改或合并什么”；按钮“发送”。
- 当对话涉及变更，AI 回复下方出现变更卡片：摘要、影响范围、私有文件保全、按钮“查看预览”。
- “应用变更”必须跳转到统一比较/预览流程；助手不能绕过确认直接写入。

#### 状态、错误与技术详情

- AI 正在思考：气泡内显示“正在准备回答…”，不显示 runner progress。
- AI 回复失败：显示“没有得到完整回答”，按钮“重试”；原消息保留。
- 网络/宿主失败：显示“助手暂时不可用”，允许继续查看中心库，不把底层错误码当正文。
- 每条任务下有折叠项“技术详情”；展开后才显示请求状态、事件时间线、日志、任务标识、模型和耗时。
- 没有对话时显示“一起检查你的 Skill 体系”，提供示例问题“帮我解释这次分析发现的重复目录”。

### 3.8 设置与隐藏高级诊断

普通设置只保留语言、主题、中心库位置（只读展示）和“数据/备份说明”。

“高级诊断”默认折叠，进入后才显示 API 地址、守护进程、安装版本、锁状态、WAL/持久化待处理数、原始 JSON 和复制诊断证据按钮。诊断页不是修复流程，也不把诊断字段映射成用户必须理解的操作。

## 4. 复杂工作区分析卡片与归并规则

### 4.1 卡片数据与组件

每张“体系”卡片至少包含：

```text
体系名称 + 一句话判断
归并结论标签（同一后端 / 内容重复 / 版本差异 / 独立体系）
来源数量与可展开路径
来源状态标签（活跃、Junction 别名、缓存镜像、休眠、声明未落盘、私有）
Skill 数 / Agent 规则数 / 文件数
差异摘要（相同、仅来源 A、仅来源 B、冲突）
用户决定（纳入中心库 / 保持独立 / 留在工作区）
查看文件与查看差异
```

卡片默认高度只展示摘要；“展开来源”才显示完整路径。对 `E:\ozdqp-main-fix` 等路径使用可复制的 `<code>` 展示，但不让路径替代名称和结论。

### 4.2 真实样本 fixture 的呈现

- **UnitySkills REST**：显示“同一体系”，来源为 `baloot_client\.agents\skills\unity-skills` 与根 `.agents\skills\unity-skills` Junction；`PackageCache 2.0.8` 拥有相同的 70 个模块文档相对路径，但 70/70 内容哈希不同，应标为“同家族缓存镜像 / 版本候选”，默认不作为活跃来源，也不得显示成“完全重复”。
- **Unity MCP CLI**：显示“同一后端家族，多个宿主投影”，来源为 `baloot_client\.agents\skills`、`.cursor\skills`、`.claude\skills`；内容完全相同时折叠，差异处显示“宿主版本有差异”。
- **AIGameTesting 私有体系**：显示“独立私有体系”，来源为 `baloot_client\Tools\AIGameTesting\agent_skills\enter-game-hall`；默认保留在工作区，必须用户明确选择才可纳入中心库。
- **Git skip-worktree 且物理缺失**：显示“休眠/隐藏记录”，列出 Git index 证据；默认不当作活跃目录，也不静默忽略。
- **`skills-lock.json` 声明但未落盘**：显示“声明未落盘”；允许查看声明内容，默认不导入和不创建空文件。

### 4.3 归并判定规则

| 场景 | 用户展示 | 默认处理 |
| --- | --- | --- |
| 内容完全重复 | “内容相同的来源” | 合并为一个体系，保留所有来源证据 |
| Junction/符号链接指向同一物理目录 | “宿主别名” | 不重复计数，显示链接方向和目标 |
| PackageCache、缓存、备份镜像 | “缓存/备份镜像” | 不作为独立体系；可查看，不主动写入 |
| 同一后端的不同宿主投影 | “同一后端，多宿主投影” | 归入同一体系，投影作为子来源 |
| 同后端但内容/版本有差异 | “同一后端，版本差异” | 保留差异，要求用户选择或合并 |
| namespace、入口和行为均不同 | “独立体系” | 独立候选，不自动合并 |
| Git index 有记录但文件缺失 | “休眠体系” | 保留证据，默认不导入、不恢复 |
| lock/manifest 声明存在但未落盘 | “声明未落盘” | 展示声明和风险，默认不创建 |
| 项目私有路径 | “私有体系” | 默认留在工作区，明确选择后才可纳入 |

归并算法可以使用路径拓扑、链接目标、文件内容指纹、入口规则、后端标识、版本信息和 Git index 状态；这些判定依据在卡片“为什么这样归并”中可读化展示。任何不确定结果必须标为“需要你决定”，不能伪装成确定合并。

## 5. 融合、接管与安全边界

### 5.1 融合进中心库

1. 只读分析工作区，列出体系和来源。
2. 用户选择要纳入、保持独立或留在工作区的体系。
3. 比较中心库当前版本与工作区内容。
4. 对冲突逐项选择中心库、工作区、手动合并或保持独立。
5. 生成预览：文件变更、体系变更、版本号、私有内容保全。
6. 用户确认“保存为中心库 v2”。
7. 产生新版本和审计摘要；原 v1 不变。

主按钮文案依次为：“继续选择”“查看比较”“解决冲突”“生成应用预览”“保存为中心库 v2”。

### 5.2 使用中心库接管此工作区

1. 只读分析工作区并展示已有体系。
2. 用户选择“使用中心库接管此工作区”。
3. 预览托管链接、规则投影、冲突路径和将被替换的 Skill 内容。
4. 单独列出“明确会写入”“一定保全”“需要你确认”。业务源码、未选择私有体系、用户脏改和 Git index 不得被默认覆盖。
5. 创建接管前恢复点；用户确认“使用中心库接管此工作区”。
6. 完成后显示工作区已连接到某中心库版本，并提供“查看接管记录”“预览恢复”。

接管取消或失败时必须显示：“未完成接管，工作区没有被继续修改”。若已经产生恢复点，应显示恢复点位置和“恢复到接管前”。任何不可逆动作都不能隐藏在“连接工作区”按钮内。

### 5.3 上游新增/更新 Skill

已连接工作区检测到别人新增或更新 Skill 时，不进入“更新中心”或连接/接管选择页。首页显示“有 N 个 Skill 被修改”，点击后进入专注的三页 `/changes` 流程：

1. **Skill 更新概览**：只展示发生变化的 Skill。每张卡包含名称、路径、新增/修改状态、用途概要、文件数、增删行数，以及“与当前版本的差异”。主按钮为“查看修改”。
2. **修改合并**：顶部是“告诉 AI 怎么处理”的对话区；下方按文件完整展开 GitHub 风格统一 diff，显示旧/新行号、删除红底和新增绿底。点击“让 AI 处理并查看成果”只生成草稿，不落库。
3. **成果审阅**：顶部提供一个统一 AI 输入区，用户通过复选框选择一个或多个作用文件，再一次说明修改要求；不再为每个文件弹出单独 AI 对话框。左侧列出全部最终文件，右侧完整展示默认可编辑的文件内容；编辑器支持文本选中、独立纵向滚动和直接输入，本次修改行使用绿色背景。每个文件只保留“确认此文件”，页面底部提供“确认全部文件”和“确认并合并到中心库”。

文件复选框只控制下一次 AI 修改范围，不等同于文件确认。人工或 AI 再次修改文件后，该文件必须回到待确认状态。只有最后的中心库确认按钮可以生成新版本；取消或稍后处理不改变中心库和来源工作区。

## 6. 中心库编辑、AI 修改、版本与回滚

### 6.1 手动修改

- 编辑器只产生草稿；顶部固定显示“草稿，不影响当前中心库版本”。
- 保存前显示文件路径、行数、体系、来源和私有内容边界。
- “查看差异”后才能启用“保存为中心库 vN”。
- 保存失败不会覆盖当前版本；保留草稿并提供重试/导出草稿。

### 6.2 AI 修改

- 助手必须先说明理解、影响和不修改范围。
- AI 输出变更集合而非直接落盘；每个变更集合可展开文件差异。
- 用户可以“接受全部建议”“逐项选择”“返回助手调整”。
- 接受后进入与融合相同的预览和版本确认，不另造 AI 专用写入通道。

### 6.3 版本规则

- 中心库版本是不可变内容集合，至少包含版本号、创建时间、来源、体系清单、文件指纹和变更摘要。
- 融合、手改、AI 修改和恢复都生成新版本；任何动作不静默修改旧版本。
- 工作区可连接到某版本；工作区上的投影状态与中心库版本分别展示。
- 取消、冲突和失败保留比较结果但不创建版本。
- 回滚通过“预览回滚 → 创建恢复版本”完成；历史链路保留。

## 7. 响应式与可访问性

- 断点：桌面双栏；平板将来源/差异改为上下堆叠；窄屏使用单列卡片和底部固定主操作栏。
- 任意路径、差异和 JSON 允许横向滚动，不让页面整体横向溢出。
- 所有卡片操作是可聚焦按钮，不依赖点击整行；键盘顺序遵循“阶段 → 内容 → 主操作 → 次操作”。
- 对比视图提供“并排 / unified diff”切换，并为新增、删除、冲突提供文本标记和图标，不只依赖颜色。
- 对话气泡、状态变化、错误提示分别使用正确的 landmark、heading 层级和 `aria-live`。
- 折叠的“技术详情”使用原生 disclosure 语义；展开状态不改变主流程焦点。
- 主按钮文字必须表达结果，例如“保存为中心库 v2”，避免“提交”“执行”“commit”。危险操作需要二次确认并说明保全边界。
