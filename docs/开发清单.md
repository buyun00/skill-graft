## 硬规则（每一步都有效）

| 规则 | 含义 |
|---|---|
| CLI 是唯一命令面 | HTTP、hook、以后的网页只 `exec` `sg` / `dist/control/cli.js`，不 `import` core |
| 第一次切换走对话 | `attach` / `detach` / 第一次改挂禁止 CLI 或测试静默跑剥离脚本 |
| 权威源在 hub | 工作树只挂链接；禁止 `-PromoteFromWorktree`、禁止把 `skills/` 推上 GitHub |
| 测真实流程，不测活树 | 冒烟用探针 worktree（现成：`E:\ozdqp-cli-attach-probe`），或新复制一棵稀疏树。禁止改正在干活的游戏仓，禁止测试里改 `ozdqp.gameRepo` 后不还原 |
| 核心不碰平台 | `src/core` 禁止 `node:http`、`powershell.exe`、Win32、`APPDATA` |
| 写盘可逆 | 幂等修链接可以不经对话；第一次剥官方必须经会话 |

**本机锚点（冒烟默认用这些，不要换活树）：**

| 角色 | 路径 |
|---|---|
| hub | `E:\ozdqp-skill-hub` |
| 命令 | 新开终端 `sg`（`sg doctor` 应全绿） |
| API | `http://127.0.0.1:18765`（守护进程保活） |
| 探针树 | `E:\ozdqp-cli-attach-probe`（`ozdqp-main-fix` 的稀疏 worktree） |
| 活树（只查不改） | `E:\ozdqp-startup-download-trace` 等已在干活的仓 |

探针被改坏时：不要修活树。重建稀疏 worktree，或从该探针自己的 git 还原，再挂。

## 1. 会话闭环 — 现在做

**系统：** 会话观测与收尾（CLI + 守护进程可帮一把，不新增产品面）。

**目的：** 发出 `sg attach` 之后，人能知道对话是在跑、成功了、还是失败了。没有这一步，后面所有「真实挂接」冒烟都只能靠翻 log，周期会继续迷。

**要实现：**

1. detached Codex 退出后回写 `skill-review/sessions.json`（`waiting` / `failed`，带 `exitCode`、`codexSessionId`、验收摘要）。
2. `sg session --id <id>`（或 `sg status` 里带进行中会话）读同一份 JSON，不要各写各的。
3. `sg attach|detach|edit --wait`：可选等到收尾再打印；默认仍立刻返回。
4. 守护进程可顺带收尸（轮询 pid / 扫 log 里的 `session id:`），但收尾规则必须在 core，CLI 与 daemon 共用。

**自动化测试：**

- 夹具 hub：假进程退出 0 / 非 0，断言 `sessions.json` 从 `running` → `waiting` / `failed`。
- CLI：`--no-spawn` 仍只入队；带 `--wait` 的测试用假 pid，不拉真 Codex。
- 禁止用活树、禁止改本机 `sessions.json` 当夹具。

**真实冒烟：**

1. 探针若已挂：先 `sg list-worktrees` 记下 `attached` / `overrideLinked` / `officialPresent`。
2. 需要再走对话时：`sg attach --worktree E:\ozdqp-cli-attach-probe --intent "清单1-会话闭环"`。
3. 立刻 `sg daemon status`、打开 `skill-review/session-*.log`，确认进程在、CLI 已返回。
4. 对话结束后（约数分钟）：`sessions.json` 不再是 `running`；`sg list-worktrees` 里该树 `attached=true`、`overrideLinked=true`、`officialPresent=false`。
5. `sg resume --id <id> --message "只报告验收字段，不要改盘"`，新一轮结束后状态回到 `waiting`。

**完成才算完：** 不翻 log 也能用 CLI 判断一轮对话的结局；`npm test` 绿；探针冒烟上述 3–5 过。

## 2. 写盘链接端口

**系统：** 适配层「能建链接」，核心仍只发命令。

**目的：** 修链、adopt 补挂、以后跨平台，不再只能调 PowerShell。本步只开端口，不改 attach 必须走对话这条规则。

**要实现：**

- `LinkPort` 增加：建目录链接（Win Junction / POSIX symlink）、建文件链接（symlink，Win 失败则 HardLink）、删链接（不跟目标内容）。
- 已有 `isLinked` / `samePath` 行为不变（仍先 realpath，再 inode+dev）。
- core 不出现 `junction` / `mklink`。

**自动化测试：** 在临时目录建 / 认 / 删；Win 上 Junction + HardLink 各至少一条（现有 A4/A5 风格）。

**真实冒烟：** 只在 `%TEMP%\sg-link-smoke\` 或探针里一个**新建的空子目录**做链接，事后删掉。禁止碰探针已有的 `.agents/skills` 和 `AGENTS.override.md`。

**完成才算完：** 测试里能不经 `.ps1` 建出可被 `isLinked` 认的链接。

## 3. `repair-links` 收回核心

**系统：** 已挂树的幂等修链（磁盘动词）。

**目的：** 断链可修、内容冲突必须失败；CLI 不再 spawn `attach-library.ps1`。第一次挂接仍禁止走这条。

**要实现：**

- `repairPlan` 已有：未挂 / 冲突 → 不写盘。
- 执行改走 core + 第 2 项端口：只修已挂名单里的树；3 Skill + override + overlay。
- 树上 override 与 hub 内容不同 → 失败并说明，不覆盖。
- CLI `repair-links` 不再调 `.ps1`。

**自动化测试：** 未挂路径不改盘（已有）；夹具树断掉 Junction 后能修回；夹具 override 改几个字节必须失败。

**真实冒烟：**

1. 确认探针已挂（否则先用第 1 项的对话挂上，不要用本命令第一次挂）。
2. 删掉探针上某一个常驻 Skill 的 Junction。
3. `sg repair-links --worktree E:\ozdqp-cli-attach-probe` 成功；`list-worktrees` 恢复。
4. 把探针 `AGENTS.override.md` 改一个字（先备份），再 repair → 必须失败；还原该文件。

**完成才算完：** CLI 源码不再出现 `attach-library.ps1`；探针上「断链能修、脏 override 拒修」。

## 4. `ingest` 收回核心

**系统：** 官方 Skill 更新入队（磁盘动词 + hook）。

**目的：** `fetch`/`pull` 只往 hub inbox 送原料，功能树不归类。hook 继续只调 `sg ingest`。

**要实现：**

- 解析 hook payload、按 pathspec 取官方 Skill / `AGENTS.md` / `CLAUDE.md`、写入 `skills/inbox/` 与 `state.json`，全部在 core + git/fs 端口。
- 空 stdin 仍是 no-op（已有）。
- `--dispatch` 只入队一条分析会话，不自动 adopt。
- CLI 不再调 `analyze-remote-skill-update.ps1`。

**自动化测试：** 空 stdin；夹具 commit range 在**隔离 HUB_ROOT** 写出 inbox，不碰本机 `skills/inbox`（已有雏形，对齐新实现）。

**真实冒烟：**

1. `HUB_ROOT` 指到临时 hub，或确认本机 inbox 可多一条测试条目。
2. 在**探针**上对一段已知含官方 Skill 的提交模拟 hook payload，管道给 `sg ingest --game-repo <探针> --dispatch`。
3. 本机（或临时 hub）`skills/inbox` 多出节点；`sg status` 的 queued +1；探针工作区业务文件不变。
4. 测完 `decide --action reject` 清掉这条测试 inbox，或只用临时 hub。

**完成才算完：** hook 路径与 CLI 手工 ingest 结果一致；活树工作区无新脏文件。

## 5. `decide` 给已挂树补链接

**系统：** inbox 拍板的后半段（adopt 真正嫁接）。

**目的：** 采用一条官方 Skill 之后，已经挂上中心方案的树立刻看见它；并入 / 拒绝仍只动 hub。

**要实现：**

- `adopt`：inbox → `skills/adopted/<name>`（已有），再对 `attached-worktrees.txt` 里每棵树补 Junction（经第 2 项端口）。
- 某棵树已有同名且不是指向 hub → 跳过并报在结果里，不覆盖。
- `merge` / `reject` 仍不改游戏树。
- 不在这里跑 Codex。

**自动化测试：** 夹具两棵「已挂」树 + 一棵未挂；adopt 后只有已挂树出现新链接；活 inbox 不被测例碰。

**真实冒烟：**

1. 用第 4 项造一条可丢弃的 inbox（名字带 `smoke-`）。
2. `sg decide --id … --action adopt`。
3. 探针 `.agents/skills/smoke-…` 指向 hub `skills/adopted/…`；活树若未在 attached 名单则没有这条。
4. `sg decide --id … --action reject` 或手动删掉 smoke adopted + 探针链接，恢复干净。

**完成才算完：** adopt 的 JSON 能看出哪些树补上了、哪些跳过；探针看得到 adopted Skill。

**真实冒烟：**

## 7. detach / edit 与 attach 同级

**系统：** 剥离与改 Skill 的会话（仍是对话，不是静默脚本）。

**目的：** 生命周期对称。现在这两条多半只入队，验收字段对不齐。

**要实现：**

- `detach` 提示词：拆链接、Restore 官方树、从 attached 名单去掉；不停手条件写清楚。
- `edit`：只改 hub 上指定 Skill；验收是 hub 文件变了、已挂树经链接能读到同一内容。
- 收尾走第 1 项的同一套 session 状态。
- CLI 自己仍不跑 Restore / 不直接改 Skill 正文。

**自动化测试：** `--no-spawn` 入队形状；结束回写（假进程）；CLI 源码不含 `manage-skill-visibility`。

**真实冒烟（只在探针）：**

1. 已挂探针上 `sg detach --worktree E:\ozdqp-cli-attach-probe --wait`。
2. 官方树回到磁盘；3 Skill 不再指向 hub；`list-worktrees.attached=false`。
3. 再 `sg attach --wait` 挂回去，字段回到第 1 项冒烟的样子。
4. `sg edit --path skills/ozdqp-development --intent "只在参考文档末尾加一行 smoke，可还原"`，确认 hub 与探针读到同一行后还原该行。

**完成才算完：** 探针能来回挂/摘一次；edit 改的是 hub 不是游戏仓副本。

## 8. inbox 分析建议

**系统：** ingest 之后的分析会话（给建议，不拍板）。

**目的：** 人看 `sg status` / 以后的网页就能看到建议 adopt / merge / reject，而不是对着一堆原始目录猜。

**要实现：**

- ingest `--dispatch` 或独立 `sg analyze` 入队 chat/analyze。
- 会话结束把建议写回 `state.json` 对应 item（`suggestion.action/target/reason`）。
- `decide` 仍必须人显式给 `--action`，建议只展示。

**自动化测试：** 假会话产出一段 JSON 建议，item 变为 `proposed`；没有 `--action` 不会 adopt。

**真实冒烟：** 第 4 项造的 inbox 跑一遍分析；`sg status` 能看到建议；再 `reject` 清掉。不要对来路不明的官方 Skill 直接 adopt。

**完成才算完：** 建议来自会话回写，不是 HTTP 或网页算出来的。
